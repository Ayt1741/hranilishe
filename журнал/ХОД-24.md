## 1. Закон 109: проверка «файл ↔ журнал» посимвольно

Написан `сверка-ответов.py`. Для каждого файла из `ответы/` он ищет в журнале запись с источником `полный ответ: ответы/<файл>` и сравнивает хеши. Три состояния, которые нельзя смешивать: **СОВПАЛО** (в журнале ровно то, что в файле), **ВЕРСИИ** (файл после записи правили), **НЕТ ЗАПИСИ** (файл есть, в журнал не попадал).

Первый прогон:

```
  ✗ ВСЕ-СООБЩЕНИЯ-с-1966.md        НЕТ ЗАПИСИ в журнале (41010 симв.)
  ✓ ОТВЕТ-одна-инструкция.md       запись №1991, 4038 симв., версий 2
  ✓ ХОД-12.md                      запись №1976, 4952 симв., версий 2
  ✗ ХОД-13.md                      НЕТ ЗАПИСИ в журнале (4341 симв.)
  ✗ ХОД-14.md                      НЕТ ЗАПИСИ в журнале (4361 симв.)
  ✗ ХОД-16.md                      НЕТ ЗАПИСИ в журнале (9326 симв.)
  …
файлов ответов: 14 · СОВПАЛО 10 · ВЕРСИИ 0 · НЕТ ЗАПИСИ 4
```

То есть четыре ответа существовали только как файлы. Если бы воркспейс пропал, эти четыре хода исчезли бы насовсем — при том что закон 109 требует дословной записи каждого ответа.

Лечение: для `память/ход.py` добавлен флаг `--пометка`, и четыре файла дописаны в журнал **с честной отметкой**, а не выданные за записи тех дней:

```
дописано 1, теперь записей 2006, последняя №2006   (ХОД-13, пометка «восстановлено 2026-11-12»)
дописано 1, теперь записей 2007, последняя №2007   (ХОД-14)
дописано 1, теперь записей 2008, последняя №2008   (ХОД-16)
дописано 1, теперь записей 2009, последняя №2009   (ВСЕ-СООБЩЕНИЯ-с-1966)

файлов ответов: 14 · СОВПАЛО 14 · ВЕРСИИ 0 · НЕТ ЗАПИСИ 0
```

Ничего не переписано и не удалено: записи добавлены в конец, в источнике стоит пометка, по ней видно, что это восстановление, а не современная запись.

## 3. Законы как данные: 95, а не 100

Написан `разбор-законов.py`: нумерация, ссылки на источники, кандидаты в противоречия, порядок блоков в панели.

```
пунктов: 95, номера 1..95, дыр 0, повторных номеров 0
пунктов без ссылки на источник: 9 — [36, 38, 21, 23, 26, 29, 30, 31, 32]
панель: «Лента действий» на позиции 3523, «Законы, которые…» на 4016 → законы НИЖЕ ленты
```

Что здесь важно:

- **Законов 95.** В моих же прошлых отчётах звучало «до 100 пунктов». Это была неточность: 100 — счётчик поисковых запросов (П3), а не число законов. Нумерация 1..95 идёт без дыр, то есть 96–100 просто не существуют.
- **У 9 пунктов нет ссылки на источник** (21, 23, 26, 29, 30, 31, 32, 36, 38) — их нечем проверить по переписке, они держатся на моём слове. Дописывать «источники» задним числом я не стал: это была бы выдумка.
- Первый прогон прибора дал **ложное «повторных номеров 5»**: в файле есть второй нумерованный список 1..5 — «Как я это проверяю каждый ход», это процедура, а не законы. Парсер их склеил. Исправлено: блок под этим заголовком пропускается.

2. «Лишнее» по п.43 — это то, что я **создаю** сам и что не нужно для дела: временные файлы, копии, черновики. Их не надо создавать, а не «надо удалять».
3. Проверочный контроль, который требует мусора, делается **вне воркспейса** — поэтому подмена журнала для контроля лежала в `/tmp`, а не рядом с памятью.

## 7. Границы

- `сверка-ответов.py` проверяет только файлы, у которых источник начинается с `полный ответ: ответы/`. Ответы, записанные с другим источником (импорт, надзор), он не увидит — и не притворяется, что увидел.
- Дословность подтверждается по хешу текста, хранящегося в журнале. Для 533 записей импорта сам хеш недоказуем (разбор хода 23), но новых файлов это не касается: у них хеш считается нашим `ход.py`.
- 95 законов — это факт файла, а не оценка. Если нужно 100, их надо формулировать заново и с источниками, а не дорисовывать номера.
