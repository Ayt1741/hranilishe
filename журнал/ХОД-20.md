```bash
bash живо.sh "что делаю" - "запрос" "команда"     # «-» = взять ход из файла
if [ -z "$TURN" ] || [ "$TURN" = "-" ]; then TURN="$(cat память/текущий-ход.txt ...)"; fi
```

Проверка синтаксиса: `bash -n живо.sh` → OK. В этом ходе первым действием сразу пошёл проход по журналу — **№144, прочитано 1995 из 1995**, и К1 зелёный.

Это не «переписал отчёт». Файл с номером хода — тот же приём, что в поиске №72: состояние живёт в файле, а не в голове; и №82: писать намерение до, результат после.

## 3. Стражи поймали настоящий баг в моём инструменте

Первый прогон контракта по ходу 20 дал **✗ К5**: «в выводе действий нет actions.json: 200 — панель не опубликована». Панель при этом была опубликована. Проверил запись №145:

```
действие №145, символов 1806, есть ли «actions.json: 200»: False
```

Причина: `панель/действие.py` обрезал вывод до **первых 1500 символов** (`ФРАГМЕНТ = 1500`), а результат публикации печатается **в конце** команды. Хвост отрезался — и проверка честно сказала, что доказательства нет.

Исправлено: вывод теперь хранится **головой и хвостом**.

```python
"вывод": (вывод if len(вывод) <= ФРАГМЕНТ
          else вывод[:ФРАГМЕНТ - 900] + "\n…(середина опущена)…\n" + вывод[-900:]),
```

Контрольный прогон, действие №146:

```
действие №146, вывод 1522 симв., маркер середины: True, есть 200: True
хвост: … | actions.json: 200 | адрес: https://ayt1741.github.io/hranilishe/panel.html | панель пересобрана и опубликована в 15:50:50 |
```

Это ровно тот класс ошибки, о котором писал поиск №52: гейт, который читает обрезанный журнал, зеленеет, ничего не проверив. Только здесь он покраснел — и это правильно.
