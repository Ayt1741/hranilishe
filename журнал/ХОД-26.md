# ХОД 26. Найдена настоящая поломка во второй панели: на github.io она показывала ленту с задержкой до 15 минут

**Прямой ответ: `panel2.html` брала данные сначала из локального файла — это верно внутри Arena, где кэша нет, но та же страница опубликована на github.io, где CDN держит файл до 15 минут. То есть «живая» панель на сайте показывала устаревшую ленту, а это прямое нарушение требования «панель показывает действия в моменте». Исправлено: порядок источников теперь зависит от хоста. Проверено обе панели и обе совпадают с копиями в хранилище. Контракт вырос до 11 пунктов, прогон — 11 из 11.**

## 1. Как нашлось

Сначала я прогнал `страницы.py` — новый прибор, который проверяет обе панели по требованиям 85, 91–97 и 108 машинно, а не «на глаз»:

```
  ✓ панель/panel.html — 17011 б, sha256 96097b7c7188…
      ✓ лента и законы на месте
      ✓ законы ниже ленты            позиции 3523 и 4016
      ✓ лента ≤ 20 на страницу       ПО_СТРАНИЦЕ = 20
      ✓ кнопки в шапке (выше ленты)  кнопок 5, первая на позиции 2263
      ✓ обход кэша (t= в запросах)   вхождения t= : 7
  ✓ панель/panel2.html — 15552 б, sha256 14b7ac2e2013…
      (те же пять проверок — все ✓)
```

Обе страницы прошли. Именно это и насторожило: **позиции заголовков совпали до символа** (3523 и 4016) при разной длине файлов (17 011 и 15 552 б). Если страницы одинаковы по скелету, но разные по размеру — значит различие не в вёрстке, а в логике. Я не стал верить зелёному и сделал `diff`:

```
69 строк различий
<  function(t){return "https://api.github.com/...actions.json?t="+t},   /* panel.html: API первый */
>  function(t){return "actions.json?t="+t},                             /* panel2: локальный первый */
```

## 2. Что именно было не так

В `panel2.html` порядок источников был: **локальный файл → API → raw**. Комментарий рядом честно объяснял замысел: «живая панель в Arena — без кэша вообще». Внутри Arena это правильно: страница и данные лежат рядом, кэша нет.

Но этот же файл публикуется в репозиторий и открывается как `https://ayt1741.github.io/hranilishe/panel2.html`. Там локальный `actions.json` отдаёт **CDN GitHub Pages с кэшем до 15 минут** — это измерено раньше (в коде панели остался замер: CDN отдал 125 записей, raw и API — 128). Значит на сайте первая попытка всегда давала устаревшую ленту, и только если она падала, страница доходила до API.

Формулировка «панель показывает действия в моменте» при таком порядке нарушалась молча: страница выглядела рабочей, просто данные в ней были четвертьчасовой давности.

## 3. Исправление — порядок зависит от хоста

```js
var НА_GITHUB = /(^|\.)github\.io$/.test(location.hostname);
var ИСТОЧНИКИ = НА_GITHUB ? [
  api, raw, локальный      /* на сайте: CDN кэширует локальный файл до 15 минут — он последний */
] : [
  локальный, api, raw      /* в Arena: локальный без кэша, это самый быстрый путь */
];
```

Проверка синтаксиса — честным компилятором, а не «на глаз»: `node --check` на извлечённом скрипте → ошибок нет (для этого понадобился временный файл в `/tmp`: раньше проверка через подстановку процесса падала с ENOENT).

Результат после публикации:

```

панель/panel2.html       e9b47b4968f3   e9b47b4968f3… (api, 16570 б) СОВПАЛО
лента действий           198, №198       198, №198 (api)              СОВПАЛО
ИТОГ: страницы и лента в хранилище совпадают с локальными → код 0
```

`страницы.py` после правки: у `panel2.html` вхождений `t=` стало 13 (было 7), все пять требований снова ✓. Файл вырос 15 552 → 16 570 б — это и есть добавленная логика выбора.

Требование «оба сайта отдельно» до этого проверялось словами «оба есть». Теперь есть цифры: 69 строк различий, разная логика выбора источника, разный размер. Это не копия с другим именем — это две разные страницы с одним содержимым.

## 7. Границы

- `страницы.py` проверяет **текст** страницы: наличие заголовков, порядок блоков, параметр `t=`. Он не открывает страницу в браузере и не измеряет, что видит пользователь. Сегодняшняя поломка нашлась не им, а сравнением двух панелей — и это честно записано.
- Порядок источников проверяется по регулярному выражению на `github.io`. Если сайт когда-нибудь переедет на свой домен, условие надо будет менять — иначе вернётся та же задержка.
