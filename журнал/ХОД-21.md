# ХОД 21. Принуждение вместо надежды: `закрыть.py`

**Прямой ответ: до этого хода контракт был проверкой, которую я запускал по своей воле. Теперь ответ физически не попадает в журнал, пока проверки не пройдены. Скрипт называется `закрыть.py`, и он уже дважды отказал мне в этом же ходе.**

## 1. Что изменилось по сути

Раньше порядок был: пишу ответ → запускаю контракт → записываю в журнал. Если бы я не запустил проверку, никто бы меня не остановил. Это ровно то, о чём поиск №54 («промпты советуют, хуки принуждают», «exit 1 не блокирует — блокирует только явный запрет») и №91 (коды 0/1/2/3, где 3 — «планку опустили»).

Теперь порядок жёсткий:

1. файл ответа существует, в нём ≥ 3 000 символов;
2. в файле есть строка `Статус: DONE | PARTIAL | NOT DONE | UNVERIFIED`;
3. гейт хода зелёный (`гейт.py --ход N`);
4. **только теперь** дозапись в журнал (`память/ход.py --файл`);
5. контракт после записи (`контракт.py --ход N`);
6. панель: собрать и опубликовать.

Отказ на шагах 1–3 — журнал **не трогается вовсе**, код возврата 1.

## 2. Доказательство фикстурами

```
$ python3 закрыть.py --тест
ФИКСТУРА «короткий ответ» → отказ: ответ 6 символов — меньше 3000, это сокращёнка
ФИКСТУРА «без строки статуса» → отказ: нет строки «Статус: DONE|PARTIAL|NOT DONE|UNVERIFIED»
ФИКСТУРА «журнал при отказе» → записей 1997 → 1997 OK: не тронут

ИТОГ ТЕСТА: отказ работает — плохой ответ в журнал не попадает
```

## 3. Живые отказы, не фикстуры — их было два

Первый: подсунул скрипту заведомо пустой ответ.

```
$ printf 'готово' > /tmp/короткий.md
$ python3 закрыть.py --ход 21 --запрос 'проверка отказа' --файл /tmp/короткий.md
ОТКАЗ: журнал не тронут.
код закрытия: 1
записей в журнале: 1997        ← было 1997 до, осталось 1997 после
```

Второй: скрипт отказал **моему настоящему ответу** на этот ход — первая редакция оказалась 2 554 символа при пороге 3 000.

```
$ python3 закрыть.py --ход 21 --запрос "продолжай составление" --файл ответы/ХОД-21.md
ЗАКРЫТИЕ ХОДА 21
 ✗ ответ: ответ 2554 символов — меньше 3000, это сокращёнка

ОТКАЗ: журнал не тронут.
```

То есть механизм сработал не на учебном примере, а на мне. Ответ пришлось переписать по существу, а не «дотянуть» водой до нужной длины — иначе он всё равно прошёл бы формально, и это остаётся слабым местом (см. §5).

## 4. Почему это важнее, чем ещё десять законов текстом

| | Текст в `ЗАКОНЫ.md` | `закрыть.py` |
|---|---|---|
| Кто отвечает за соблюдение | я, по памяти | код, при каждом закрытии |
| Что при нарушении | ничего, кроме укора в чате | журнал не пополняется, код 1 |
| Забывается после сжатия контекста | да (поиск №58: выживает 17 % правил) | нет, скрипт лежит на диске |
| Стоит токенов контекста | 100 пунктов | 0 |

Отдельно про то, почему проверка стоит **до** записи, а не после: по поиску №82 на каждое действие надо писать намерение до и результат после — «лог, который просто обрывается, — самая частая форма реального инцидента». Здесь то же самое: сначала отказ, потом запись.

## 5. Что остаётся честной границей

- **Я могу не вызвать `закрыть.py` вообще** и написать ответ прямо в чат. Тогда в журнале не будет записи, это будет видно по нумерации, но автоматически меня никто не остановит: Stop-хука в этой среде у меня нет (поиски №54 и №91).
- **Скрипт проверяет размер, статус, гейт и контракт — но не смысл.** Ответ на 3 000 символов из воды пройдёт.
- **Порог 3 000 — моя выдумка, а не измерение.** Его надо подбирать по факту: если законные короткие ответы начнут отклоняться, порог станет вредным (поиск №60: блокировать больше 2–3 % законных действий — значит страж и есть баг).
- **`закрыть.py` теперь в манифесте** (защищённых файлов 5, путей 12), поэтому молча его ослабить нельзя: правка даст код 3 «планку опустили».
