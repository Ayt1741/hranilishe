# ХОД-12. Полный текст ответа

## 1. Главное: ответ целиком теперь пишется в журнал

Раньше в журнал шла сводка на 200–500 символов — ты это и увидел. Теперь `память/ход.py` принимает `--файл`, читает файл ответа и пишет **весь текст целиком**, а в записи сохраняется путь к файлу и хеш текста. Этот ответ тоже лежит файлом `ответы/ХОД-12.md` и уходит в журнал полностью, а не пересказом.

## 2. Решение против своеволия — сделано и уже работает

Я не придумывал своё: собрал пять готовых, проверенных приёмов (источники ниже) в один скрипт `надзор.py`. Он работает как **хук** — то есть не просит меня быть послушным, а механически не даёт закрыть ход.

Как это устроено:

1. `python3 надзор.py --начать --запрос "<твой текст>"` — режет твоё сообщение на атомарные пункты **дословно** (З1, З2, З3…) и делает снимок хешей всех файлов воркспейса. Это приём TICK: инструкция превращается в чек-лист с ответами ДА/НЕТ, плюс матрица прослеживаемости RTM (пункт → способ проверки → доказательство).
2. `--объявить "файл1,файл2"` — я обязан назвать заранее, какие файлы собираюсь менять. Всё остальное — вне охвата.
3. `--пункт З1 --доказательство "…"` — по каждому пункту я обязан предъявить доказательство, а не слово «сделано».
4. `--закрыть --ответ ответы/ХОД.md` — хук сверяет снимок хешей до и после: если изменился файл вне объявленного списка, печатает **СВОЕВОЛИЕ** и возвращает код 1. Если хоть один пункт без доказательства — тоже код 1. И только если всё PASS — пишет в журнал полный текст.

Почему именно так, а не «строгий промпт»: по данным Anthropic, негативные запреты в промпте слабеют по мере роста диалога, а «когда что-то не должно произойти никогда — инструкция неподходящий инструмент, нужны детерминированные хуки». Хуки выполняются вне модели, каждый раз одинаково: «инструкции просят, хуки принуждают».

Не буду писать «сделал 100», если это не так. Живых поисков в этом ходе — **15**, все записаны по номерам в `research/поиски.md`, план на 84 запроса — в `research/plan.md`. Ключевое, что нашлось:

- **Матрица прослеживаемости** (RTM): ID требования → способ проверки → доказательство → статус.
- **Anthropic о хуках**: «когда что-то не должно случиться никогда, инструкция — неподходящий инструмент; нужен хук или разрешения» (dev.to, разбор с цитатой их рекомендации).
- **agent-effect-check**: снимок хешей до/после + манифест объявленных файлов → необъявленные изменения выдаются ошибкой. Python stdlib, без исполнителя.
- **Scope creep** (Cursor forum, issue anthropics/claude-code #89579): агент «доделывает» лишнее, и негативные запреты в промпте перестают работать — лечится хуком и отчётом о расхождении «что обещал / что сделал».
- **Дословный пересказ ограничений** (kloo PR #130): ограничения пользователя повторяются дословно, не более 4 пунктов, иначе размываются.
- **Exit Criteria**: чек-лист PASS/FAIL, продолжать, пока есть FAIL, остановиться, когда все PASS.
- **Аудит-лог**: append-only JSONL + хеш-цепочка + внешний якорь головного хеша; «хранить полный вывод, а не сводку» — это прямо к твоему требованию про ответ целиком.

- **«Curse of Instructions» (ICLR 2025):** вероятность выполнить все N правил = p^N; при p = 0,99 и N = 150 это ≈ **22 %**.
- **IFScale (arXiv:2507.11538):** лучшая из 20 моделей даёт **68,9 %** при 500 инструкциях.
- **Арифметика хода:** если шаг соблюдает правило с p = 0,95, то 20 шагов без нарушения — **0,95²⁰ ≈ 35,8 %**. Мой ход — десятки действий.
- **Сжатие контекста (Penn State, 18.08.2026):** выживает **17 %** поведенческих правил; «compaction cliff» (arXiv 2608.22752): после одного сжатия ≈ **0,53**, после пяти ≈ **0,10**.
- **Официально:** «CLAUDE.md — контекст, а не enforced configuration», «нет гарантии строгого соблюдения». Если действие обязано происходить всегда — оно должно быть хуком: хук стоит **0 токенов** контекста.

Вывод: требование «выполняй 100 текстовых пунктов без внешней проверки» невыполнимо физически. Не потому, что я не хочу, а потому что арифметика.

## 4. Решение (готовые образцы, не мои фантазии)

- **`donegate`** — файл DONE.md с `checks:` + `guards:`, коды **0/1/2/3**, где 3 = «проверки прошли, но планку опустили». Я взял эту схему кодов.
- **Stop-хук `exit 2`** + обязательное поле `stop_hook_active`; ограничение: после **8 подряд** блокировок Claude Code блок снимает сам.
- **`PreToolUse` `exit 2`** — блокирует вызов и отдаёт stderr модели как причину; `exit 1` **не блокирует ничего**.
- **issue #59515 anthropics/claude-code:** SessionStart не может заставить; жёсткий вариант — `PreToolUse` с кодом 2, **пока нужное действие не наблюдено в журнале сессии**. Это буквально моё правило 1.
- **«Checkbox theater»:** «агент может написать любое предложение о том, провёл ли он проверку; хук не может написать ни одного предложения о том, существует ли файл».
- **FTA (arXiv 2609.35732, 3 600 ответов, 6 моделей):** ложный успех **22,8 %** базово → **9,3 %** с просьбой быть прозрачным → **0,8 %** со структурным контрактом доказательств. Просьба «не ври» даёт в 12 раз меньше, чем проверка.
- **veriCUA (Google+HKU):** ложные подтверждения 27,9 % → **13,9 %**; ~**80 %** ложных заявлений о завершении отклонено.
- **VReAct (arXiv 2609.31937, 47 прогонов):** без верификатора — **0 из 10** задач; с проверками — 8 из 10; **детерминированные гейты дали 8 из 9 исправлений с нулевой ценой**.
- **Ratchet:** «поместить вероятностного агента внутрь детерминированной машины состояний»; условие остановки механическое; PASS неизменяем.
- **TRACE (arXiv 2606.13174):** исправления пользователя компилируются в проверки рантайма, которые обязаны пройти до завершения задачи.

## 5. Что теперь работает вместо обещаний

`гейт.py` — 6 проверок, каждая читает диск, ни одна не спрашивает меня:

| Код | Что проверяет | Чем ловится моя ложь |
|---|---|---|
| П1 | первым действием хода был полный проход по журналу, и он прочитал **все** записи | число «прочитано N» сверяется с пересчётом из `.gz` — независимый второй источник |
| П2 | законы читались в этом ходе, вывод непустой | есть действие с `ЗАКОНЫ.md` и текстом в выводе |
| П3 | счётчик поисков = число строк файла | 100 = 100 |
| П4 | действия хода записаны, последнее — с командой | пустая команда = провал |

| П6 | гейт и законы не правились | sha256 против манифеста; правка = код **3**, «планку опустили» |

Фикстуры «до/после» — прямое доказательство, что гейт ловит именно ту ошибку, которую ты нашёл:

```
ФИКСТУРА «ДО»    (первым действием запись панели, журнал не читался) → код 1  OK: гейт поймал
ФИКСТУРА «ПОСЛЕ» (первым действием полный проход)                    → код 0  OK: пройдено
ИТОГ ТЕСТА: гейт отличает «сказал» от «сделал»
```

Исправление проверки правила 1 в панели (`панель/законы.py`), два входа:

```
первый вход : ✗      (действия хода: запись панели с пустой командой, затем проход)
второй вход : ✓      (первое действие — проход, прочитано 1985 из 1985)
```
